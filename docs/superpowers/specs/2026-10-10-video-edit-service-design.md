# video.edit — сервис монтажа коротких видео

Дизайн-документ. Дата: 2026-10-10. Владелец и единственный пользователь: Павел.

Макеты экранов (живые, можно нажимать): https://claude.ai/artifact/UfqK2GZKXY7qtWU9JeGjm6

## 1. Зачем

Павел снимает вертикальные видео «говорящая голова» (Reels / TikTok / Shorts) — по-русски и на других языках
(см. `2026-10-10-multilingual-design.md`).
Раньше монтаж шёл в чате с Claude по скиллу `video-montage` (ветка
`ccr-8e46a501-g3fmtt` репозитория `PavelMalachovski/Mluv.Me`, папка
`.claude/skills/video-montage/`): вырезать паузы и оговорки, 9:16, вшитые субтитры
с подсветкой слова, шкала времени, заголовок, анимированные вставки там, куда автор
показывает рукой.

Что мешало:
- в чат нельзя загрузить файл больше ~30 МБ, обходной путь через черновик релиза
  GitHub Павел делал руками;
- каждый раз нужно открывать чат и вести Claude по шагам.

Нужно: **залить видео с телефона на веб-страницу → ответить на вопросы → выбрать
стиль по превью → получить готовый ролик.** Без открытия чата с Claude. Под капотом
монтажом управляет Claude (Claude Code), и работает он **по подписке Павла**, а не
по платному API-ключу.

## 2. Цели, не-цели, анти-цели

**Цели**
- С телефона, в обычном браузере: загрузка видео любого разумного размера (сотни МБ,
  до ~2 ГБ).
- Сервис сам запускает Claude, тот анализирует видео и задаёт вопросы.
- Три превью стиля (A, B, C) на настоящем кадре из видео; выбор шрифта и цветов
  с мгновенным предпросмотром.
- Вставки там, где автор просит в кадре («добавь сюда …»), из `assets/` или загруженной
  картинки.
- Готовый ролик (MP4 1080×1920) и `.srt` скачиваются со страницы.
- Правка «Поправить» свободным текстом → новый рендер.
- На странице живой статус каждой фазы.

**Не-цели**
- Несколько пользователей, регистрация, биллинг (пока так; путь к ним — `2026-10-12-editor-and-saas-design.md`, §7).
- Работа через Claude API по ключу (решение Павла: только подписка).
- Публикация в соцсети, ~~таймлайн-редактор~~ (отменено 12.10.2026 — редактор с дорожками,
  `2026-10-12-editor-and-saas-design.md`), уведомления в Telegram/почту.
- Автоматическое обучение стиля по выборам Павла.

**Анти-цели (провал, даже если «работает»)**
- Сервис сам меняет правила в `SKILL.md`. Правила меняет **только Павел**.
- Превью не совпадает с финальным роликом (другой шрифт, цвет, размер, место).
- Потеря исходника или готового ролика.
- Долгоживущий токен с правом записи в GitHub попадает в браузер.
- Для обычного видео нужно открыть чат с Claude или что-то сделать руками в GitHub.

## 3. Решения Павла

1. Сервис работает сам, без чата.
2. Пользователь один — Павел.
3. Поток: загрузка → вопросы → превью → монтаж → результат (см. макеты).
4. Веб-часть на **Vercel**; Railway можно использовать для остального, если нужно.
5. Claude работает **по подписке** через **Claude Code Routines** (облачные сессии),
   а не через API-ключ и не через `claude setup-token` на своём сервере.
6. Статус: на сайте, по фазам, без внешних уведомлений.
7. Правила монтажа живут в `SKILL.md` в репозитории video.edit, меняет их только Павел.
8. Превью — **три** варианта.
9. На экране превью можно выбрать **шрифт и цвета**.
10. Хранилище — приватный репозиторий `PavelMalachovski/video.edit` (он приватный).
11. **Вставки** (логотипы, стикеры, анимации там, где автор говорит «добавь сюда») —
    **в первой версии**. Картинки — из папки `assets/` в video.edit, её ведёт Павел.
12. Телефон — **iPhone**.
13. Подписка — **Max**.
14. ~~Речь только русская~~ — отменено: ролик целиком на любом языке на латинице или кириллице, субтитры на
    языке речи (`2026-10-10-multilingual-design.md`); смешанной речи в одном ролике нет.
15. Из скилла «Claude-монтажёр reels» (maysoulme,
    https://github.com/maiyamaiya19999-bit/claude-montage-skill) берём в первую версию
    четыре блока приёмов (подробно — 5.9), но **не её фирменный вид** (полоски, градиент,
    её шрифты и музыку):
    - **динамика** — ускорение **×1.1** (не ×1.3), резка пауз **мягкая** (не агрессивная),
      зумы по смыслу речи;
    - **звук** — фоновая музыка с приглушением под речью, звуки появления вставок;
    - **тексты** — хук с рукописным последним словом, титр с кодовым словом,
      субтитры слово за словом, звёздочки в «денежных» словах;
    - **вставки+** — полноэкранные перебивки видео, постоянная библиотека вставок
      «по смыслу», ТЗ в свободной форме при загрузке.

## 4. Как это выглядит для Павла

Экраны — в макетах (ссылка вверху). Тексты в макетах примерные.

1. **Загрузка.** Кнопка «Выбрать видео» (галерея телефона, можно несколько частей —
   склеиваются по порядку), прогресс загрузки. Необязательно: поле **«ТЗ»** свободным
   текстом (хук, кодовое слово, музыка, «когда говорю X — покажи Y», «фуллскрин …»,
   слова для звёздочек) и кнопка **«Вставки для этого ролика»** (картинки и видео из
   галереи). Что указано в ТЗ, Claude уже не спрашивает. Ниже «Мои видео» со статусами.
2. **Ожидание анализа.** У видео живой статус по фазам: «Запускаю сессию»,
   «Скачиваю видео», «Расшифровываю», «Смотрю кадры», «Готовлю вопросы». Страницу
   можно закрыть; видео в работе — вверху списка. Когда нужен ответ — карточка
   жёлтая: «Ждёт ответов».
3. **Вопросы.** Claude задаёт вопросы по этому видео, кнопками и полями. Типичные:
   резать ли паузы и оговорки (с цифрами: «14 пауз, 2 повтора, будет ~1:16»);
   хук (предложенный / свой / без; последнее слово станет рукописным); кодовое слово,
   если в речи есть «пишите мне слово …»; музыка (треки из `assets/music/` / без
   музыки); в каких словах ставить звёздочки (найденные «денежные» слова);
   какие вставки из библиотеки поставить и на каких фразах (Claude предлагает,
   Павел подтверждает); «как пишется это слово» (имена, бренды);
   что поставить там, где автор сказал «добавь сюда …» (с миниатюрой кадра и
   отметкой, куда он показывает; варианты — картинки из `assets/`, стикер с текстом,
   «загрузить свою картинку», «не надо»); стоп-кадр в конце. Набор вопросов Claude
   выбирает сам по видео и по `SKILL.md`; вопросов без смысла для этого видео нет.
4. **Превью.** Сразу после ответов, без нового запуска Claude. Один настоящий кадр из
   видео в трёх стилях:
   - **A** — строго по `SKILL.md` (домашний стиль Павла);
   - **B** и **C** — вариации, в каждой заметно меняется что-то (подача субтитров:
     обводка с подсветкой / плашка / слово за словом с накоплением / по одному слову
     крупно, место шкалы, подача хука, цвет).
   Под тремя миниатюрами — крупный предпросмотр выбранного варианта (с хуком и
   субтитрами); ниже выбор **шрифта** (кураторский список шрифтов с кириллицей),
   **рукописного шрифта** для акцентного слова хука и кодового слова (кириллические
   рукописные) и **цветов**: подсветка слова, текст, шкала времени — готовые образцы
   плюс «Свой» (палитра). Всё меняется
   мгновенно. Поле «Ни один не подходит? Скажи, что поменять» → «Ещё три варианта»
   (новый запуск Claude, новые A/B/C). Кнопка «Монтировать».
5. **Монтаж.** Живой статус фаз.
6. **Готово.** Плеер, «Скачать видео», «Субтитры .srt», список «что я сделал»
   (что вырезано, где вставки, в каком стиле), слова, в которых Claude не уверен.
   Поле «Поправить» → «Переделать» → новый рендер этого же видео.

Ошибка на любом шаге: карточка красная, понятный текст, кнопка «Повторить».

## 5. Устройство

```
 Телефон (браузер)
     │  страница, вопросы, превью, статусы
     ▼
 Vercel: веб-приложение + API-роуты (пароль, токены GitHub — только на сервере)
     │ 1) создать задачу, принять загрузку     │ 2) «запусти шаг»: POST в Routine API
     ▼                                         ▼
 GitHub: PavelMalachovski/video.edit     Claude Code Routine (облачная сессия,
   - черновик релиза на задачу:            подписка Павла)
     исходник, готовый ролик                 - клонирует video.edit
   - ветка задачи: статус, вопросы,          - скилл .claude/skills/video-montage
     ответы, кадры, стили, результат         - ffmpeg, whisper, Chromium
   - .claude/skills/video-montage/           - пишет статусы и результаты в GitHub
     SKILL.md (правила), скрипты
```

### 5.1 Веб-часть (Vercel)
- Next.js (решение строителя, если не будет причин против), мобильная вёрстка по макетам.
- Вход по паролю (переменная окружения), сессия в httpOnly-cookie.
- Все обращения к GitHub — через серверные API-роуты; токен GitHub (fine-grained PAT
  или GitHub App с доступом только к video.edit) хранится в переменных Vercel.
- Опрос статуса задачи каждые ~5 с, пока страница открыта.
- Превью рендерятся **в браузере** тем же HTML-шаблоном стиля, что и финал (см. 5.5).
- Лимит тела запроса функции Vercel ~4,5 МБ: видео идёт через функции Vercel
  **кусками по 4 МБ** (см. 5.2).

### 5.2 Загрузка видео
**Решено по итогам проверок** (`docs/spikes/2026-10-results.md`, задача 3).
Павел заливает видео **с компьютера** (браузер); с телефона страница тоже работает,
но Safari на iPhone не проверялся (решение Павла).
- Браузер режет файл на куски по 4 МБ (лимит тела функции Vercel ~4,5 МБ) и шлёт их
  `PUT /api/jobs/<id>/parts/<n>`; функция кладёт каждый кусок ассетом
  `source.part-NNNNN` в черновик `job-<id>`. Токен GitHub — только на сервере.
- Очередь: 4 запроса параллельно, ≥ 750 мс между стартами (вторичные лимиты GitHub
  на создание ассетов — до 80 в минуту; было 2 и 700 мс, но кусок идёт ~4 с туда и обратно, и загрузка стояла на
  2 МБ/с — 24.10.2026), повтор с нарастающей паузой, 60 с после ответа «лимит»,
  продолжение с уже загруженных кусков («Продолжить загрузку»).
- В конце `complete` сверяет число кусков и сумму размеров и пишет `manifest.json`
  (имя, размер, тип, число кусков, время). Задача считается загруженной, когда есть
  манифест.
- Сессия скачивает куски REST-запросом без своего токена и склеивает по порядку имён.
- Замер: 2,08 ГБ с iPhone (4K HEVC, 4,4 мин) — 11,7 мин загрузки, байт в байт.
- Несколько частей одного видео — следующая версия (сейчас одна задача = один файл).

### 5.3 Запуск Claude (Routines)
Документация: https://code.claude.com/docs/en/routines (research preview).
- Одна рутина «video-edit» в облачном окружении с репозиторием video.edit.
  Создаёт её Павел в интерфейсе claude.ai/code (строитель пишет пошаговую инструкцию),
  включает **API-триггер**; токен триггера кладётся в переменные Vercel.
- Запуск шага: `POST https://api.anthropic.com/v1/claude_code/routines/<id>/fire`,
  `Authorization: Bearer <токен рутины>`, заголовки `anthropic-version: 2023-06-01`
  и `anthropic-beta: experimental-cc-routine-2026-04-01`, тело `{"text": "..."}`;
  ответ — `{claude_code_session_id, claude_code_session_url}` (проверено).
  В `text` — только JSON `{job, step, attempt}`. Документация предупреждает, что
  `text` приходит как недоверенные данные: промпт рутины должен говорить, что
  делать с этим JSON, а всё содержимое задачи (ответы Павла и т. п.) сессия читает
  из GitHub, а не из `text`.
- Шаги: `analyze` (анализ + вопросы + кадры + стили), `restyle` («ещё три варианта»),
  `render` (финал), `fix` («Поправить»). Типичное видео = **2 запуска**
  (`analyze`, `render`).
- Замер: от запуска до первого коммита сессии — 130 с (холодный старт) и 35 с
  (тёплый). Рутина пушит в `claude/job-<job>` (своя назначенная ветка ей не мешает).
- Рутина Павла: `trig_01EnWeSuCDA6Yu36ZUjnmaZM` (создаётся и меняется только в
  интерфейсе claude.ai/code; агент её запускать не может).
- Лимиты из документации: 30 запусков API в час на рутину, 100 в час на аккаунт.
  Запуски тратят лимиты подписки, как обычный чат. Дневные лимиты не документированы.
- Модель рутины — на усмотрение строителя/Павла (настройка рутины). У Павла Max,
  так что сильная модель допустима; тяжёлое и механическое всё равно держать в
  скриптах, а не в рассуждениях модели.
- Если Routine API поменяется (бета-заголовок) — сломается только роут запуска;
  держать его в одном месте.

### 5.4 Облачное окружение
По документации (https://code.claude.com/docs/en/cloud-environments): ~4 vCPU,
16 ГБ RAM, 30 ГБ диска (приблизительно), Ubuntu 24.04, скрипт подготовки от root.
- Скрипт подготовки — `setup/cloud-setup.sh`, вставлен целиком в Setup script
  окружения: ffmpeg, распознавание (GigaAM v2 — слова и время, Whisper turbo — текст
  с пунктуацией, Silero VAD; всё с GitHub, huggingface.co закрыт), Playwright с
  Chromium из образа. С нуля ~95 с, повторно секунды — кэшируется.
- **Видео с iPhone**: HEVC, бывает HDR (HLG / Dolby Vision 8.4), бывает 4K и 60 к/с;
  первый настоящий ролик Павла — 4K HEVC SDR, ~30 к/с, поворот −90. HDR приводится к
  SDR прямым `zscale` (`t=bt709:m=bt709:p=bt709:r=tv:npl=100`) до извлечения
  `frame.png`.
  Финал — H.264 без B-кадров, 1080×1920, 30 к/с, SDR, стерео AAC 192 кбит/с; в MP4 нет edit lists (так требует Meta).
- Распознавание — на языке ролика (GigaAM для русского, Parakeet и Whisper для других), шрифт должен иметь все
  буквы ролика (`2026-10-10-multilingual-design.md`).
- github.com и objects.githubusercontent.com доступны по умолчанию. Другие домены
  (Railway, Vercel) из сессии недоступны, пока их не добавить в настройки сети
  окружения — по возможности сессии ходят только в GitHub.

### 5.5 Стиль: одна разметка для превью и финала
Требование: превью = финал. Поэтому:
- Стиль описывается **спецификацией** (JSON): шрифт, цвета (текст, подсветка,
  шкала, плашка), режим субтитров (обводка / плашка / по слову; слов на экране),
  положение субтитров, режим и положение заголовка, положение и толщина шкалы.
- Один HTML/CSS-шаблон рисует слой «субтитры + заголовок + шкала» по спецификации
  и моменту времени. Страница использует его для превью поверх настоящего кадра.
  Финальный рендер использует **тот же шаблон** в Chromium (как `overlay/render.js`
  прошлого скилла рисует вставки) и накладывает кадры ffmpeg-ом. Если строитель
  выберет другой путь (например, ASS/libass для субтитров), он должен показать,
  что превью и финал совпадают по шрифту, размеру, цвету и месту.
- Шрифты — кураторский список с кириллицей (в макете: Montserrat, Unbounded, Rubik,
  Oswald, Russo One, Comfortaa); один и тот же файл шрифта в браузере и в рендере.
- A строится из правил `SKILL.md`; B и C — Claude предлагает вариации. Выбор Павла
  (вариант + шрифт + цвета) сохраняется в задаче и применяется **только к этому ролику**.

### 5.6 Данные задачи
Задача = id (короткий, читаемый), черновик релиза `job-<id>` и ветка задачи.
- **Черновик релиза** (приватный репозиторий, черновик виден только соавторам):
  исходные части, готовый `final.mp4`, `final.srt`.
- **Ветка задачи** `claude/job-<id>` (рутине пушить в неё можно — проверено),
  папка `jobs/<id>/` (тяжёлое — в `jobs/<id>/work/`, она не коммитится):
  - `job.json` — имя файла, длительность, создано, текущее состояние;
  - `status.json` — фаза, текст фазы, прогресс, время, что ждём от Павла, ошибка;
  - `questions.json` — вопросы по схеме, которую понимает страница
    (выбор из вариантов / текст / проверка слова / вставка с картинкой; ответ
    по умолчанию);
  - `answers.json` — ответы Павла, выбранный стиль и его правки;
  - `styles.json` — три спецификации A/B/C;
  - `frame.png` (кадр для превью), картинки к вопросам;
  - рабочие файлы Claude: расшифровка, исправленные субтитры, решения по нарезке,
    чтобы `render` и `fix` не распознавали речь заново;
  - `result.json` — что сделано, сомнительные слова, история правок.
- Состояния (`status.json`): `uploading → queued → analyzing → waiting_answers →
  queued → rendering → rendered`; ролик готов, когда в ветке есть `out/released.json`
  с `final*.mp4`; из готового — `fix` обратно в `rendering`; из любого — `error`.
- Сессия коммитит `status.json` на каждой смене фазы — так страница видит прогресс.

**Готовые файлы (проверено):** сессии запрещено создавать, менять и удалять релизы и
удалять ветки. Поэтому сессия пушит `out/final*.mp4` и `.srt` в ветку задачи (файлы
больше 95 МБ — частями `.part-aa…` + `.sha256`), а Action `job-outputs` склеивает их,
кладёт в черновик `job-<id>`, убирает из ветки и пишет `out/released.json`.
Скачивание для Павла — через роут Vercel. Удаление задачи (черновик + ветка) делает
веб-часть токеном Павла.

Ролики до ~5 минут — целевой предел (моё решение; длиннее — страница предупреждает,
но не запрещает).

### 5.7 Скилл монтажа
- Перенести `.claude/skills/video-montage/` из ветки `ccr-8e46a501-g3fmtt` Mluv.Me в
  video.edit: `edit_video.py` (нарезка пауз/оговорок/повторов), `transcribe.py`
  (субтитры по островкам речи), `finish.py` (9:16, звук, сборка), `overlay/`
  (вставки в Chromium), `setup.sh`, `whisper_sherpa.py`. Сохранить файл лицензии.
- `SKILL.md` делится на две части:
  - **«Правила»** — то, что правит Павел: цвета, шрифты, слов на экране, место шкалы,
    громкость, скорость, как резать паузы, зумы, музыка, звёздочки и т. п. Стартовое
    содержимое — правила прошлого скилла (жёлтая подсветка слова, 2–3 слова,
    Montserrat, шкала внизу всегда, субтитры всегда, 9:16 1080×1920, вставки не на
    лицо и не в зоны интерфейса соцсетей, текст субтитров сверяет Claude, «в сомнении —
    оставь») **плюс приёмы из 5.9** с их значениями по умолчанию.
  - **«Как работает сервис»** — шаги `analyze` / `restyle` / `render` / `fix`, схема
    файлов задачи, как писать статусы. Сервис эту часть не меняет во время работы.
- Всё, что в прошлом скилле было «спроси пользователя в чате», теперь становится
  вопросом в `questions.json` (на шаге `analyze`) или пунктом «не уверен» в
  `result.json` (после рендера).
- Шаг `analyze` должен успеть всё, что нужно для вопросов **и** превью: черновая
  нарезка, субтитры с правкой текста, поиск моментов «добавь сюда» (кадры с сеткой,
  куда показывает палец), выбор кадра для превью, три спецификации стиля.

### 5.8 Вставки (первая версия)
- Типы из прошлого скилла (`overlay/overlay.html`): `badge` (иконка + текст),
  `sticker` (заголовок + текст), `image` (готовая картинка), анимации вроде `bachata`.
  Рендер — Chromium, как раньше; вставки не на лицо и не в зоны интерфейса соцсетей
  (верх ~250 px, низ ~350 px кадра 1920).
- **`assets/`** в video.edit ведёт Павел, с коротким `assets/README.md`: что есть что.
  Структура: `logos/` (логотипы), `library/` (постоянные вставки на все ролики:
  скрины, мемы, стикеры, демо-видео — с понятными именами), `music/`, `sfx/`
  (звуки появления: свуш, поп), `fonts/` (свои шрифты, если хочется сверх
  кураторского списка). Claude открывает и **смотрит** каждую картинку, а не
  судит по имени файла.
- Вставки для одного ролика Павел прикрепляет при загрузке (п. 1 раздела 4);
  они живут в задаче, не в `assets/`.
- Подбор из `library/` «по смыслу» — только если картинка прямо поддерживает
  сказанное; сомнение — не ставить. Каждая вставка привязана к конкретной фразе.
- В ответе на вопрос о вставке можно **загрузить свою картинку** с телефона — она
  кладётся в задачу (не в `assets/`); Павел сам решает, переносить ли её в `assets/`.
- Логотипы реальных компаний, которых нет в `assets/` и которые Павел не загрузил,
  Claude не выдумывает: предлагает стикер с текстом.
- Новый тип анимации, если нужен, Claude может дописать **в рамках задачи** (в ветке
  задачи), не меняя общий скилл в `master`.
- Вставки видны и на превью (тот же шаблон), чтобы Павел видел, где они встанут.
- Появление и оформление — см. 5.9 «Вставки+».

### 5.9 Монтажные приёмы (из скилла maysoulme, адаптировано)
Значения по умолчанию; все попадают в «Правила» `SKILL.md`, Павел может менять.
Источник — открытый `SKILL.md` maysoulme (лицензии в репозитории нет): берём приёмы
и числа, **не берём** её файлы (полоски, градиент, шрифты Heading Now / Helvetica
Neue / Denistina, трек «flashing lights»).

**Динамика**
- Ускорение всего ролика **×1.1**, тон голоса сохраняется (видео `setpts`, звук
  `atempo`). Все тайминги (субтитры, вставки, хук) — по ускоренной шкале.
- Резка пауз **мягкая**: убирать фальстарты, повторы и длинные паузы, но оставлять
  естественные вдохи; ориентир — паузы длиннее ~0,4–0,5 с ужимать до ~0,15–0,2 с,
  тишину в начале и конце убирать полностью. Точные пороги — подобрать на реальных
  видео (основа — `edit_video.py` прошлого скилла).
- Зумы по смыслу речи (тезис, контраст, панчлайн — ближе; новая мысль — назад):
  уровни 1.00 / 1.08 / 1.10 / 1.14 (максимум 1.16; было 1.04–1.07 и 1.08 — Павел попросил вдвое ближе), плавный переход ~0,45 с, якорь —
  лицо, примерно 3–6 смен на 30 с, не по таймеру. Зум только на исходник;
  субтитры, хук и шкала не зумятся.

**Звук**
- Голос: `loudnorm` I=−14 LUFS, TP=−1.5, LRA=11 (тихая запись — ещё шумоподавление).
- Музыка (если выбрана): с первого кадра до последнего, на 14 дБ тише голоса — трек сначала выравнивается к его
  громкости (дизайн стиля эталона, п. 17), приглушение на −2…−4 дБ под речью, мягкие вход и выход; не ускоряется.
- Звук появления каждой вставки из `assets/sfx/` (свуш — для скринов, поп — для
  стикеров), около −13 дБ, точно на первом кадре появления. Нет звуков в `sfx/` —
  вставки без звука и пометка в отчёте.

**Тексты**
- **Хук**: в начале ролика, ~2–3 с. Все слова кроме последнего — основным шрифтом
  капсом; последнее — рукописным, крупнее, другим цветом, «свисает» под строкой
  (позиционировать по реальным границам букв). Пока виден хук — вставок нет.
- **Титр с кодовым словом**: если в речи есть призыв «пишите мне слово …» — титр
  той же конструкции на этой фразе (±0,2 с), кодовое слово рукописным.
- **Субтитры**: режим «слово за словом с накоплением» — блок из 3–6 слов
  раскладывается заранее, слова появляются в момент произнесения, уже показанные не
  сдвигаются. Это один из режимов спецификации стиля наряду с обводкой и подсветкой,
  плашкой и одним словом крупно (5.5); какой режим в варианте A — решают правила.
- **Звёздочки** по умолчанию в «денежных» и рискованных для алгоритмов словах
  (р*блей, бесплатн*, подп*ска …) плюс слова из ТЗ; Павел подтверждает список
  в вопросах.
- Рукописные шрифты — с кириллицей (например Caveat, Marck Script, Bad Script из
  Google Fonts) или свой из `assets/fonts/`.

**Вставки+**
- Появление резкое: ~85 мс, прозрачность 0→1 и масштаб 0,965→1,00, без «пружины»;
  показ минимум 1,5 с. Прямоугольные — скругление 10 px, рамка 1 px #111, лёгкая
  тень; PNG без фона — тонкий контур по силуэту. Без кропа, поворотов и фильтров.
- **Полноэкранная перебивка**: видео-вставка «на весь экран» (из ТЗ или из `library/`
  на подходящей фразе) — кадр резко переключается целиком; горизонтальное видео
  масштабируется по высоте и обрезается по центру; звук вставки выключен, голос
  продолжается; субтитры и шкала остаются поверх.
- ТЗ при загрузке понимает: `ХУК:`, `КОДОВОЕ СЛОВО:`, `МУЗЫКА:`, `ЦЕНЗУРА:`,
  «когда говорю X — покажи Y», «фуллскрин <что>», и обычный текст.

**Качество (берём как есть)**
- Безопасная зона для всех элементов (с тенью и обводкой): X 60–890, Y 120–1530
  на кадре 1080×1920; не закрывать лицо (+40 px) и субтитры (+20 px). Исключения —
  полноэкранные перебивки.
- Лёгкий цветокор говорящей головы (после перевода HDR в SDR): кожа естественная,
  заметный фильтр — переделать.
- Перед полным рендером — 4 контрольных кадра (хук / субтитры / вставка / кодовое
  слово) и проверка геометрии.
- Не отдавать ролик, если: субтитры не на месте или прыгают; хук или кодовое слово
  забыты; буквы пересекаются; вставка на лице, на субтитрах или вне безопасной зоны;
  музыка не с первого кадра (если выбрана). Чего-то не хватает (нет музыки, шрифта,
  звуков) — монтировать без этого и явно сказать в итогах.

- Репозиторий video.edit приватный; ветка по умолчанию `master`.

## 8. Кто что настраивает
Строитель готовит в репозитории весь код, конфиги и пошаговые инструкции
(`docs/setup.md`). Павел по инструкции делает то, что требует его аккаунтов:
подключает video.edit к Vercel и задаёт переменные окружения; создаёт токен GitHub
(или GitHub App); создаёт облачное окружение и рутину в claude.ai/code, включает
API-триггер и вставляет его токен в Vercel; при необходимости — сервис на Railway.
Проверки с телефона (iPhone) делает Павел. План строится так, чтобы таких передач
было мало и каждая была короткой.

## 9. Первые проверки (до основной разработки) — сделаны
Результаты и решения — `docs/spikes/2026-10-results.md`: загрузка (2,08 ГБ, байт в байт),
рутина по API (старт 35–130 с), инструменты в облачной сессии (время слов ±40 мс,
HDR→SDR, рендер слоя 82 мс/кадр), готовые файлы через Action `job-outputs`.

## 10. Как поймём, что готово
С iPhone, не открывая чат с Claude: загрузить реальное видео на 1–2 минуты (HDR, как
снимает телефон) с коротким ТЗ (хук, одна вставка «когда говорю X — покажи Y») →
увидеть фазы → ответить на вопросы, в том числе выбрать логотип из `assets/` для
«добавь сюда» и трек из `assets/music/` → выбрать вариант, шрифт, рукописный шрифт и
цвета → получить ролик, где субтитры, хук, шкала и вставки выглядят как на выбранном
превью; речь чуть быстрее, без длинных пауз, но не «задыхается»; есть зумы по смыслу,
музыка под голосом и звуки появления вставок; цвета кожи естественные → нажать
«Поправить» и получить исправленный ролик.

## 11. Решения, принятые автором документа (проверь)
- Превью рисуются в браузере тем же шаблоном, что и финал; отдельный запуск Claude
  ради превью не нужен (типичное видео = 2 запуска).
- Вход на страницу — по паролю.
- Исходники и ролики — в черновиках релизов; рабочие файлы — в ветке задачи.
- Стартовые правила `SKILL.md` — из прошлого скилла.
- В ответе о вставке можно загрузить свою картинку; она не попадает в `assets/` сама.
- Целевая длина ролика — до ~5 минут.
- Выбор стиля, шрифта и цветов действует только на этот ролик.
- Из скилла maysoulme: мягкая резка — ориентир «паузы > ~0,4–0,5 с ужимать до
  ~0,15–0,2 с»; хук держится ~2–3 с (а не 5 с, как заголовок в прошлом скилле);
  звёздочки включены по умолчанию, но список Павел подтверждает; её фирменные файлы
  не используем; рукописный шрифт — кириллический (у неё Denistina, похоже, только
  латиница).
- Хук и кодовое слово — тот же HTML-шаблон, что субтитры, чтобы превью совпадало.
