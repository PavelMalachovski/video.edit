# Ролик — в черновик без GitHub Actions — 26.10.2026

## 1. Что было
26.10 ролик `jwup` (12 с) смонтировался, но не дошёл до Павла: с 10:46 UTC все запуски Actions падали за 2–3 с без
единого шага (машина не выдавалась — кончились минуты или лимит расходов; минуты в месяце съел CI). Готовые файлы из
`jobs/<id>/out/` в черновик релиза переносил Action `job-outputs` — без него ролик лежал в ветке, а сессия сочла это
ошибкой.

## 2. Решение Павла
Перенос — без Actions, самой страницей.

## 3. Что решил строитель
- Переносит страница (`web/lib/outputs.ts`, `deliverOutputs`) после ответа на опрос задачи или редактора
  (`deliverLater`, `after()`): Павел открыл страницу — ролик появится на следующем опросе. Те же правила, что у
  `move-job-outputs.sh`: части `<имя>.part-aa…` склеиваются по порядку и сверяются с `<имя>.sha256`, файл того же имени
  в черновике заменяется, `out/released.json` — список ассетов.
- По файлу за раз, сначала ролик (`final.mp4`, `final-vN.mp4`), после каждого — коммит; новый файл начинается, только
  пока не прошло 30 с (у функции 60 с). Не успели — перенесётся на следующем опросе.
- Из ветки файл убирается, только если он там тот же (сессия не перезалила его, пока шёл перенос — сверка по sha блоба)
  и в черновике лежит целиком (догруженный ассет того же размера); `released.json` — по свежему списку черновика, без
  оборванных загрузок (`state: starter`). Так параллельный перенос с другого экземпляра или оборванный по времени ничего
  не теряет. Файл заменяется всегда, даже того же размера (после ревью: субтитры с исправленной буквой — те же байты).
- Сумма не сошлась — этот файл остаётся в ветке, остальные переносятся. Черновика нет (задачу удаляют) — ничего не
  делается и черновик не создаётся.
- Action `job-outputs` — только вручную (запасной); сессии в SKILL.md сказано Actions не ждать.

- Вечером 26.10 редактор `jwup` не запускал видео: файлы задачи разом переносили два экземпляра страницы (и вернувшийся
  Action), прокси в черновике заменили, а в `released.json` остался id прежнего ассета — `/media` отвечал 502, плеер
  стоял. Повторено локально (тот же сбой на мёртвом id). Исправлено двумя слоями: замок переноса в черновике
  (`delivering.lock` — имя ассета уникально; брошенный старше 3 мин перехватывается) и `releasedDownload`: id из
  `released.json` не найден — файл берётся по имени из живого черновика, `released.json` переписывается (так чинятся и
  уже сломанные задачи, в том числе `jwup`, — при первом же запросе видео).

## 4. Отложено
- Перенос, только когда страницу открыли: файлы анализа (маска, прокси) дойдут к рендеру, если Павел открыл задачу
  (он открывает её, чтобы ответить на вопросы); иначе рендер посчитает маску сам — дольше, не ошибка.
- Части больше 100 МБ в памяти функции целиком (до ~3× размера файла); потоковая загрузка — если ролики станут длиннее.
- Подпапка в `out/` держала бы флаг переноса (`hasOutputs` смотрит только имена) — сессия их не делает.
