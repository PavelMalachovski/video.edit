# video.edit: редактор с дорожками (как veed) и путь к SaaS — дизайн и план по фазам

Дата: 2026-10-12. Эталон — veed.io (скриншоты Павла: редактор с левой рельсой инструментов, кадром в центре и
таймлайном внизу; панели Video, Audio, AI Tools). Главный дизайн сервиса — `2026-10-10-video-edit-service-design.md`;
этот документ меняет в нём не-цель «таймлайн-редактор» и добавляет путь к нескольким пользователям.

## 1. Что просил Павел
Сделать из проекта полноценный SaaS по образцу veed.io: звуковая и видео дорожка для пользователя, вход через Google,
модель очистки голоса (видео снято в шумном месте — улица, машины). План — по фазам, выполнять потихоньку, вопросы —
по ходу.

## 2. Решения Павла (12.10.2026, ответы на вопросы)
1. **Сейчас сервис — для Павла, на том, что есть**: Vercel, GitHub как хранилище, монтаж — облачная сессия Claude
   (рутина) по подписке Max. Сначала — интерфейс. Инфраструктура для чужих пользователей (база, хранилище, свой
   вычислитель, Claude по API) — потом (§7).
   - Ответ «закрытая бета» (раунд 1) и «гибрид: механика — движок, умное — Claude по API» (раунд 1) уточнены в
     раунде 3: «другим не надо, только для меня, через веб на Vercel, как сейчас». Их выводы — в §7, на будущее.
2. **Таймлайн — полный ручной редактор**, как veed, а не только просмотр автомонтажа.
3. **Первая версия таймлайна умеет всё четыре группы**: разрезать / обрезать / удалить / вернуть вырезанное;
   переставлять куски и монтировать из нескольких файлов; звук — громкость, mute, сдвиг музыки, звуки; текст и вставки
   на таймлайне (сдвигать и растягивать по времени, править слова).
4. **Редактор — главный экран задачи**: загрузка → анализ → вопросы → редактор с черновиком на таймлайне (стиль,
   шрифт, цвета — в его панелях) → «Монтировать» → готовый ролик открывается в том же редакторе для правок.
   Экран «Превью» вливается в редактор.
5. **Компьютер прежде всего**, телефон — проще (загрузка, вопросы, просмотр, простые правки).
6. **Вид — светлый, как veed** (новая тема; тёмная «Монтажка» от 11.10 уходит).
7. **Начинаем с кликабельного макета**, код — после правок по макету.
8. **Порядок: сначала таймлайн**, очистка голоса — следующей.
9. **Очистка голоса — переключатель и подсказка**: «Очистить голос» на дорожке голоса, сила Мягко / Норма / Максимум,
   «до/после»; если движок слышит шум — «Похоже, шумно — включить?». В вопросах автомонтажа — вопрос с прослушкой.
10. **Интерфейс — русский и английский** (словари сразу, язык — по браузеру, переключатель).
11. **Формат кадра — 9:16**; в данных проекта формат — поле, чтобы 1:1, 4:5, 16:9 добавить без переделки.
12. **Старый поток работает, пока новый не готов**; потом переезд и выключение старого.
13. **Ассеты (на будущее, для других пользователей)**: общая библиотека (только то, что можно раздавать) плюс своё у
    каждого; логотипы, бренд и личный стиль Павла — только у Павла.
14. **Чат с Claude (фаза 5б) — рутиной по подписке Павла, без Claude API** (13.10): сервисом пока пользуется только
    Павел; подписку — когда сам всё проверит.

Не-цель «таймлайн-редактор» в главном дизайне (§2) — **отменена** этим решением.

## 3. Что выяснили (разбор кода и исследование, 12.10.2026)

### 3.1 Подписка Claude и чужие ролики
Монтировать ролики других людей на подписке Max нельзя. Страница Claude Code «Legal and compliance»
(https://code.claude.com/docs/en/legal-and-compliance): «Anthropic does not permit third-party developers … to route
requests through Free, Pro, or Max plan credentials on behalf of their users»; лимиты Pro/Max «assume ordinary,
individual usage». Usage Policy запрещает «services that route requests through consumer subscriptions»; рутины
принадлежат личному аккаунту и тратят его лимиты (https://code.claude.com/docs/en/routines). Пока пользователь один —
Павел — всё в порядке. Для чужих роликов — только API-ключ по Commercial Terms (§7).

### 3.2 Таймлайн: свой, рендер — наш движок
Готовые редакторы не подходят: каждый рисует финал сам (в браузере или в своём облаке) — превью разойдётся с финалом,
а правило «превью = финал» — анти-цель главного дизайна. И лицензии: Etro — GPL-3.0; Twick — запрет SaaS без договора;
Shotstack Studio SDK — PolyForm Shield (запрет конкурировать); IMG.LY — не редактирует видео в Safari и на телефонах;
Remotion — Player в редакторе = тариф «Automators» от $100/мес; классический OpenCut (MIT) — в архиве с 17.05.2026,
годится как образец кода. **Делаем свой таймлайн на React; финал рендерит движок `vm`.**

Что для этого нужно (сейчас на странице нет ни видео, ни звука — только один кадр `frame.png`):
- **Прокси-видео** H.264 540×960, частые ключевые кадры, `faststart` — исходник с iPhone (4K HEVC, бывает HDR) в
  Chrome на Windows может не играть. Делает сессия на `analyze` из уже нормализованного `source.mp4`.
- **Пики звука** (`peaks.json`, numpy) и **лента кадров** (спрайт) — для дорожек.
- **Отдача видео в браузер**: функции Vercel отдают не больше ~4,5 МБ за ответ, а Safari требует запросы по кускам
  (Range, ответ 206). Маршрут страницы отдаёт прокси кусками до 4 МБ (браузер сам просит следующие), токен GitHub —
  только на сервере. Для одного пользователя этого достаточно; для SaaS — объектное хранилище (§7).
- **Звук превью — через Web Audio**: на iPhone громкость `<video>` не меняется (всегда 1), громкость дорожек и «до/после»
  очистки — только через узлы усиления. Свой адрес (тот же сайт) — Web Audio работает без CORS.
- **Текст в превью при проигрывании** рисует тот же `template/` (как сейчас на кадре): события слоя
  `[{t0,t1,state}]` считает движок (`build_overlay_events`); для мгновенного превью правок — перенос сборки субтитров и
  событий слоя на TypeScript с общими фикстурами (новая пара «меняются только вместе»).
- Зум, ч/б, затемнение фона, переходы рисует только ffmpeg — сейчас их нет и на превью-кадре. Решение — в фазе 5
  (приблизить CSS по тем же формулам и сверить тестом, или «черновой рендер куска» по кнопке).

### 3.3 Движок: что умеет и что придётся менять
- Все решения монтажа — в `jobs/<id>/edit.json` (пишет только сессия, время — исходника). Картинка — `keep`: куски
  одного `source.mp4` **строго по возрастанию**, без перекрытий (`engine/vm/timeline.py:47-51`), одна скорость на ролик;
  повтор куска — только `teaser`. Звук режется теми же границами кадров, отдельной звуковой дорожки нет.
- Без переделки движок уже рендерит: обрезку, удаление и разрезание кусков (это правка `keep`), исправленные слова,
  место и время вставок, зумы, скорость, `music.gainDb`.
- Не выражается сейчас: перестановка кусков, несколько исходников, громкость и mute голоса, сдвиг и обрезка музыки,
  громкость каждого звука, звук отдельно от картинки. Для этого — **таймлайн v2** (§4.3): список клипов вместо `keep`,
  `Timeline` — отображение «один исходник → много мест», `_cut` и `audio_graph` — по клипам и дорожкам.
- Каждый запуск рутины заново скачивает и нормализует исходник (минуты на 4K) и стартует 35–130 с. Для таймлайна это
  значит: правки руками копятся на странице и уходят одним «Монтировать», а не по одной.

### 3.4 Очистка голоса: модель выбрана, проверена в нашем контейнере
- Сейчас: ffmpeg `afftdn` и только для тихих записей (< −30 LUFS, `engine/vm/audio.py:25-28`). Уличный шум в нормальной
  по громкости записи не трогается; на шуме `afftdn` оценку не улучшает (DNSMOS OVRL 1,13 против 1,19 у исходника).
- **Основная — DPDFNet2-48k** (`dpdfnet2_48khz_hr.onnx`, Apache-2.0, 10,6 МБ) через уже установленный sherpa-onnx
  (≥ 1.13.5), 48 кГц, на CPU: 60 с звука за 15–16,5 с (RTF 0,26–0,28 на 4 vCPU). Скачивается из GitHub-релиза
  `k2-fsa/sherpa-onnx` `speech-enhancement-models` — Hugging Face не нужен.
- **Вторая в A/B и запасная — DeepFilterNet3** (`deep-filter` 0.5.6, MIT/Apache, одна программа с GitHub, RTF 0,35).
- Проверочный прогон DNSMOS на одном синтетическом ролике (стационарный шум, **не** улица): исходник 1,19; afftdn 1,13;
  arnndn 2,01; DF3 2,63; DPDFNet2-48k 2,82. Уличный шум и ветер публично никто не сравнивал — выбираем по роликам Павла.
- **Сила = подмешивание исходника**: `выход = исходник·10^(−A/20) + чистый·(1 − 10^(−A/20))` (так устроен «предел
  подавления» DeepFilterNet). Чистую дорожку считаем один раз на полную силу, а силу превью задаёт громкость сухой
  дорожки в Web Audio, финал — та же формула в ffmpeg. Превью = финал, смена силы не требует нового прогона модели.
  Пресеты: Мягко 12 дБ, Норма 18 дБ (как −18 дБ по умолчанию у veed Clean Audio API), Максимум 100.
- **Распознавание — на исходном звуке**: исследования 2022–2025 показывают, что чистка перед Whisper часто увеличивает
  ошибки из-за артефактов (arXiv 2201.06685, 2512.17562); для GigaAM данных нет. Проверим A/B по WER.
- Место в движке: `normalize` пишет второй выход того же звукового графа без потерь (`work/voice.wav`, 48 кГц,
  ровно кадры × 1600 отсчётов) → модель → `work/voice-clean.wav` той же длины (задержка модели компенсирована) →
  `render._cut` берёт голос из него вместо `[0:a]` (режет по номерам отсчётов — синхрон сохраняется). Кэш — по
  исходнику и имени модели, как маска затемнения.
- Не берём: Meta Denoiser (CC-BY-NC), Demucs (обучен на музыке, в архиве), Adobe Podcast (нет API), Auphonic для
  коротких роликов (минимум 3 минуты к оплате). Внешние API (VEED Clean Audio на fal.ai $0,0125/мин, ElevenLabs Voice
  Isolator $0,10–0,12/мин) — только после A/B и решения Павла, можно ли отдавать звук третьей стороне.

## 4. Как будет устроено

### 4.1 Поток задачи
Загрузка (одно или несколько видео, ТЗ, вставки, озвучка) → анализ (сессия, как сейчас; плюс прокси, пики, лента
кадров) → вопросы → **редактор** с черновиком монтажа на таймлайне → «Монтировать» (`render`) → готовый ролик — в том
же редакторе: правки руками → «Монтировать» снова; «Поправить» текстом → `fix`. Старый поток с экраном «Превью» живёт
рядом, пока новый не готов (решение 12).

### 4.2 Экран редактора (компьютер)
Светлый, раскладка veed (решение 6), но своё имя и свой значок — ни логотипа, ни названия veed:
- **Шапка**: назад к «Мои видео», имя ролика, отмена/повтор, «Монтировать» (главная кнопка), после рендера — «Скачать».
- **Левая рельса** и панель при ней: Медиа (исходники и вставки задачи, «Добавить видео»), Аудио (музыка, звуки,
  озвучка), Субтитры, Текст (хук, призыв, акценты), Стиль (варианты A/B/C, шрифт, цвета — то, что сейчас на «Превью»),
  Бренд, AI-инструменты (очистить голос, паузы и слова-паразиты, «Поправить» текстом, «Ещё три варианта»), Настройки
  (скорость, обложка, версии).
- **Кадр 9:16** в центре: прокси + слой `template/`; ручки места хука, субтитров, вставок — как сейчас.
- **Таймлайн** внизу: плейхед, тайм-коды, зум; дорожки «Видео» (куски, вырезанное серым — «вернуть»), «Голос» (волна,
  громкость, mute, «Очистить голос»), «Музыка», «Звуки», «Субтитры», «Текст», «Вставки». Клавиши: пробел — пуск,
  S — разрезать, Delete — удалить кусок, ⌘/Ctrl+Z — отмена. Привязка — к границам слов и пауз (лучше, чем к сетке у veed).
- **Телефон**: просмотр, вопросы, стиль, простые правки (разрезать и удалить кусок, mute), без многодорожечного
  таймлайна — так же поступает veed (веб-проекты на телефоне не правятся).

### 4.3 Данные: таймлайн v2 (`jobs/<id>/timeline.json`)
- Время — целые кадры при 30 к/с (как у движка). Формат кадра — поле (`9:16`).
- `assets`: исходники и вставки задачи (ссылки на загрузки).
- `tracks.video`: клипы `{id, asset, in, out, speed?}` подряд (магнитная главная дорожка, без дыр); `tracks.voice`:
  звук клипов (связан с видео), `gainDb`, `muted`, `clean: {on, strengthDb}`; `tracks.music` и `tracks.sfx`: клипы
  `{id, asset, in, out, at, gainDb, fadeIn, fadeOut}`; `tracks.text`: субтитры (группы слов), хук, призыв, акценты;
  `tracks.inserts`: вставки `{t0, t1, box}`.
- Ревизия (`rev`): страница пишет без `force` и повторяет при гонке (правило «ветку задачи не переписывать»).
- Кто пишет: черновик — сессия на `analyze` (из черновика `edit.json`); дальше — страница; `render` монтирует из
  `timeline.json`; `fix` — сессия меняет в нём только то, что попросили (правки руками не теряются).
- Новых шагов рутины не вводим (её промпт Павел вставляет руками): прокси и пики делает `analyze`, `render` берёт
  `timeline.json`, если он есть. Если без нового шага не обойтись — задача Павлу обновить промпт рутины.
- Схема `engine/vm/schemas/timeline.json` и типы `web/lib/timeline.ts` — новая пара «меняются только вместе»; общая
  фикстура: таймлайн из одного исходника по порядку рендерится **так же**, как сегодняшний `keep` (без регресса).
- SKILL.md, часть 2 (как работает сервис) — новые файлы и кто их пишет; часть 1 (правила Павла) не трогаем. Правило
  звука про очистку голоса (часть 1, §5) — предлагаю текст, вносит Павел.

### Фаза 1 — кликабельный макет (сейчас)
- Живая страница-макет редактора на компьютере (и вид на телефоне): рельса и панели, кадр 9:16 с субтитрами, таймлайн
  с дорожками; работают пуск, плейхед, зум, разрезать, удалить/вернуть, перетащить кусок, громкость и mute дорожки,
  сдвиг музыки, перетаскивание и растяжение текста и вставок, «Очистить голос» с силой, отмена. Данные — примерные.
- Исходник — `docs/mockups/editor/editor.html`, макет — https://claude.ai/artifact/9LwzYfsaUys1S5rrN5dQPt. Павел
  смотрит и пишет правки; итог — в §8 и в раскладку фазы 2.

### Фаза 2 — каркас редактора на настоящей задаче
- Новая светлая тема (токены цвета), каркас ru/en (словари, переключатель).
- `analyze` дополнительно делает прокси, `peaks.json`, ленту кадров (новые выходы — через `out/` и Action или в ветку
  файлом < 95 МБ — решу в фазе).
- Маршрут отдачи прокси кусками с Range (206).
- TS-перенос `Timeline` (исходник ↔ финал) с общей фикстурой.
- Экран редактора: кадр с плеером, таймлайн **только показывает** черновик (`edit.json` → дорожки), стиль/шрифт/цвета —
  в панелях (переносим с «Превью»), «Монтировать» — как сейчас.
- Готово, когда: на задаче Павла видно и слышно черновик монтажа на дорожках; e2e проходит новый путь; старый
  поток не сломан.

### Фаза 3 — правки на таймлайне без переделки движка
- Чистые функции на TS (тест сначала): разрезать, обрезать края, удалить со сдвигом, вернуть вырезанное, привязка к
  словам, паузам, плейхеду и краям; зум; отмена и повтор.
- `timeline.json` v2 (для одного исходника по порядку) и сохранение; `render` монтирует из него.
- Звук: громкость и mute голоса и музыки, сдвиг и обрезка музыки, затухания, громкость каждого звука (небольшая правка
  `audio_graph`). Превью звука — Web Audio.

### Фаза 4 — движок v2: перестановка и несколько файлов
- Загрузка нескольких видео в задачу (сейчас одна задача = один файл).
- `Timeline` — список клипов (один кусок исходника может стоять где угодно и не один раз); `_cut`, маска затемнения,
  субтитры, зумы, переходы — по клипам. Общая фикстура «один исходник по порядку = как раньше».
- На таймлайне — перетаскивание кусков, клипы из «Медиа». Плеер — два `<video>` попеременно (смена исходника = склейка).

### Фаза 5 — текст и вставки на таймлайне
- Перенос сборки субтитров (`subs.build_sub_events`) и событий слоя (`overlay.build_overlay_events`) на TS — общие
  фикстуры, сгенерированные движком (пары «меняются только вместе»).
- Блоки хука, призыва, акцентов, вставок — сдвиг и растяжение; правка слов субтитров; при проигрывании текст в
  превью — как в финале.
- Решение по зуму, ч/б, затемнению, переходам в превью (CSS по формулам движка или черновой рендер куска).

### Фаза 5б — чат с Claude рядом с редактором (идея Павла, 12.10)
- Справа от кадра — чат: Павел пишет словами («убери паузы во втором куске», «музыку тише и позже», «кусок про
  приложение — в начало», «субтитры крупнее»), Claude меняет дорожки — видео, голос, музыку, звуки, текст и вставки, —
  и это сразу видно и слышно в редакторе. Каждая правка чата — такая же правка, как руками: видна на дорожках,
  отменяется и повторяется, «Монтировать» — как сейчас. Цель — редактор удобнее veed и аналогов.
- Опора — то, что уже есть: правки руками (`timeline.json`: вырезать, вернуть, переставить, разрезать, громкость,
  музыка), стиль (`answers.json.style`), после фазы 5 — текст и вставки на таймлайне. Чат предлагает те же правки:
  движок и «превью = финал» не меняются.
- Чем отвечает чат — решил Павел (13.10, §2 п. 14): **рутиной по подписке**, без ключа API. Каждая реплика —
  запуск сессии, ответ через 1–3 мин. Открытый вопрос к Павлу: правки чата — сразу (с отменой) или предложением
  «Применить».
- Проверка — как всего редактора: e2e в Chromium и Safari, скриншоты каждого шага в ветках `ci-screens/…`.

## 6. Риски
- **Задержка правок**: каждый рендер — холодный старт рутины и нормализация исходника заново. Смягчение: правки копятся
  и уходят одним «Монтировать»; в SaaS — свой вычислитель с кэшем (§7).
- **Превью = финал на проигрывании**: всё, что рисует ffmpeg (зум, ч/б, затемнение, переходы), в плеере приблизительно
  (фаза 5). Звук превью (Web Audio) не повторит `loudnorm` и ограничитель бит в бит — допускаем разницу в громкости, но
  не в составе и времени.
- **Два места одной логики** (TS и Python): только с общими фикстурами, которые генерирует движок.
- **Лимиты GitHub**: автосохранение таймлайна коммитами — редко (по паузе в правках и при «Монтировать»), не на каждое
  движение.
- **Музыка**: в `assets/music` — чужие треки; для Павла можно, другим раздавать нельзя (§7).

## 7. Потом: SaaS для других пользователей (что выяснили, чтобы не потерять)
Не делаем сейчас (решение 1). Цены — со страниц сервисов на 12.10.2026.
- **Claude по API-ключу** (Commercial Terms разрешают продукт для своих клиентов, DPA включён). Конвейер из 2–4
  структурированных вызовов (анализ → вопросы и стили; план → таймлайн; «Поправить»): ~$0,35–0,55 за ролик на
  Sonnet 5.5 ($2/$10 за млн токенов), ~$0,7–1,1 на Opus 5.5 ($4/$20). Агент как сейчас (Managed Agents, $0,08 за
  час работы + токены) — ~$3–4 за ролик. Claude — 85–90% стоимости сервиса. Agent SDK в продукте для других — только
  после письменного подтверждения Anthropic. Источник: https://platform.claude.com/docs/en/about-claude/pricing
- **Вход и база**: Better Auth (MIT; Auth.js v5 так и не вышел из беты и только поддерживается) + Neon Postgres через
  Vercel (бесплатно на старте) + Drizzle; тесты — PGlite и memory-адаптер под `node --test`. У каждой строки — владелец
  (`owner_id`). Для бета-теста — список приглашённых.
- **Хранилище**: Cloudflare R2 — $0,015/ГБ·мес, скачивание бесплатно, загрузка из браузера напрямую кусками (до
  10 000 частей), удаление старого по правилам.
- **Вычислитель**: Modal (CPU по секундам, $30/мес бесплатно, GPU при нужде) с образом из `setup/cloud-setup.sh`;
  очередь — в Postgres (pg-boss / pgmq). Hetzner — выгоднее от ~500–1000 активных пользователей.
- **Оценка в месяц** (10 роликов на пользователя): 10 пользователей ≈ $60–80 (Sonnet), 100 ≈ $420–640,
  1000 ≈ $4,2–6,5 тыс.
- **Оплата**: Paddle (5% + $0,50, НДС берёт на себя) или Stripe Billing + OSS (если Павел плательщик НДС в Чехии);
  Lemon Squeezy — не начинать (уходит в Stripe Managed Payments).
- **GDPR**: политика, договоры с обработчиками, срок хранения и удаление видео, процедура на 72 часа при утечке.
- **Музыка и ассеты**: для других — только с правом раздачи (лицензионная библиотека) плюс свои загрузки.
- **Изоляция**: сейчас сессия может писать в любую ветку репозитория, а `releaseId` берётся у браузера (IDOR) — для
  одного пользователя безопасно, для многих — закрыть в первой же фазе SaaS.
- Образец: VEED OpenEdit (Apache-2.0, 08.2026) — их агентный монтаж в Claude Code почти один в один с нашим устройством
  (EDL, HTML-слой в headless Chrome, приглушение музыки, −14 LUFS).

## 8. Что решил строитель
1. **Таймлайн — свой, рендер — только движок** (§3.2): иначе два рендера и превью ≠ финал; готовые редакторы не
   проходят по лицензии или по Safari.
2. **Новых шагов рутины не вводим**, пока можно обойтись (§4.3): промпт рутины Павел вставляет руками.
3. **Порядок внутри таймлайна** — от того, что движок умеет уже сейчас (фаза 3), к переделке движка (фаза 4) и
   переносу текста (фаза 5): каждая фаза сама по себе полезна и проверяема.
4. **Вход через Google — без базы**: для одного пользователя достаточно OIDC и подписанной cookie со списком почт;
   Better Auth и база — вместе с SaaS (§7).

5. **Проверка на настоящем ролике (12.10, фаза 1)** — `docs/mockups/editor/real.html` и `real-check/`: первые 30 с
   IMG_8524 в редакторе с настоящим видео и звуком, «Монтировать» → рендер движком здесь же. Что выяснили для фазы 2:
   - движок рендерит таймлайн из одного исходника без доработок: 30 с 4K → `vm prepare` 43 с, `vm render` 77 с на
     4 vCPU; длина 16,7 с против 16,8 с на превью — границы кусков движок ставит по кадрам 30 к/с, TS-перенос
     `Timeline` должен делать то же;
   - прокси 540×960 с ключевым кадром каждые 0,5 с — 2 МБ на 30 с; переход по кускам — перемотка одного `<video>`,
     часы — звук голоса (`<audio>` с `preservesPitch`, скорость ×1,2 без «бурундука»);
   - голос до/после очистки — одним стереофайлом (слева исходный, справа чистый): сила очистки — громкость каналов
     в Web Audio, рассинхрона двух плееров нет;
   - Chromium из Playwright не играет H.264/AAC: e2e плеера — на копиях WebM/Opus или на канале Chrome;
   - текст на превью пока приближение стиля (в финале — `template/`): фаза 5 обязательна для «превью = финал»;
   - этот ролик снят в тихой комнате (фон ≈ −81 дБ) — проверка очистки голоса нужна на записях с улицы (фаза 6).

6. **Фаза 2 — двумя частями.** 2а (сделана 12.10): файлы редактора, плеер и дорожки черновика только для показа,
   светлая тема и RU/EN — в редакторе; 2б: панели стиля (вариант, шрифт, цвета, затемнение) в редакторе. «Монтировать»
   в 2а ведёт на старый экран — там ответы на вопросы, без которых монтажа нет.
7. **Файлы редактора делает `vm prepare`** (шаг рутины не новый): `out/proxy.mp4` (540×960, ключевой кадр 0,5 с,
   картинка и звук вместе — до 75 МБ, с запасом до 95 МБ git) уходит с обычным `vm push` и тем же Action, что ролики, в черновик релиза;
   `film.jpg` (кадр каждые 0,5 с, не больше 1000) и `editor.json` (длина, прокси, лента, волна — 50 пиков в секунду
   base64) лежат в ветке. Делается один раз — пока нет `editor.json`; 30 с исходника 4K — 10 с, прокси 1,8 МБ. У задач,
   разобранных раньше, файлы появятся на их следующем шаге (prepare делает недостающее).
8. **Прокси — ссылкой на ассет**: `/api/jobs/<id>/media?name=proxy.mp4` отвечает 302 на подписанную ссылку GitHub,
   она сама отдаёт куски по Range — свой маршрут с Range не нужен. Ссылка истекает — плеер берёт адрес заново и встаёт
   на то же место. Звук — в самом прокси (AAC); пара «до/после очистки» появится в фазе 6.
9. **Плеер — куски подряд одним `<video>`**: время финала → кусок → перемотка, скорость монтажа через `playbackRate`
   (тон не меняется). `Timeline` на TS — тот же, что у движка, общая фикстура `timeline-map.json`; границы кусков по
   кадрам движок ставит только при рендере — на дорожках возможна разница в кадр на склейку.
10. **Текст на кадре редактора — приближение**: тот же шаблон, но группы субтитров считает `overlayAt` проще, чем
    `build_sub_events` движка; точно — в фазе 5. На экране это сказано.
11. **Светлая тема — токены `--e-*` на `.ed`**, остальной сайт тёмный; язык — `localStorage['vm:lang']`, только в редакторе.
12. **e2e**: прокси — WebM (Chromium из Playwright без H.264), поддельный GitHub отдаёт ассеты кусками по Range.

13. **Фаза 2б (12.10): стиль — в панели редактора.** Вариант, шрифт, рукописный, три цвета и затемнение под
    субтитрами — справа от кадра, в светлой теме. Выбор — тот же, что на «Превью» (`localStorage['vm:style:<id>']`):
    поменял в редакторе — «Монтировать» на старом экране возьмёт его. Ролик уже смонтирован — панель показывает его
    стиль (`answers.style`) и не меняет: новый стиль — при монтаже из редактора (фаза 3). Черновика ещё нет — на
    кадре кадр-образец сессии с текстом-образцом (как на «Превью»), стиль видно и так. Шрифты шаблона страница грузит
    один раз на документ (`app/use-fonts.ts`), общий для «Превью» и редактора.

14. **Фаза 3 (12.10): правки руками — поверх черновика сессии, движок кладёт их сам.**
    - Правки — операции во времени исходника в `timeline.json` (`edits`: вырезать, вернуть, разрезать; `voice`,
      `music`, `sounds` — громкость, «без звука», где звучит музыка), а не новый таймлайн: сессия по ответам и правкам
      текстом пишет `edit.json` как раньше, а `vm render` и `vm check` кладут правки Павла поверх (`edits.edit_of`) —
      вырезанное руками не возвращается, когда сессия перепишет `keep`. Новых шагов рутины нет; таймлайн из клипов
      (§4.3: несколько файлов, перестановка) — фаза 4.
    - Правило кусков одно на TS и Python (`applyKeep` ↔ `apply_keep`, общая фикстура `edits.json`): кусок короче кадра
      после правки не остаётся, последний кусок удалить нельзя. Края кусков тянутся мышью и липнут к границам слов
      (ближе 8 px); перетаскивать кусок целиком — фаза 4. Отмена и повтор — до 200 шагов, шаги одного ползунка — один.
    - Сохранение — само, через 1,2 с после правки: `PUT /api/jobs/<id>/timeline` пишет ревизию base + 1 без force.
      Другая ревизия в ветке (правили во второй вкладке) — конфликт «Загрузить их»; проверка — на той голове, поверх
      которой коммит (`commitFiles` считает файлы от головы на каждой попытке). Пока Claude монтирует — правки закрыты.
    - «Монтировать»: до монтажа — старый экран с вопросами (`render` возьмёт правки сам); у готового ролика — правка
      `fix` с `timeline` (ревизия) и `style: true`, если Павел поменял стиль в панели (новый — сразу в `answers.json`,
      прошлый — `styleFrom` в правке): сессия для стиля делает `vm style --onto` (новый выбор поверх стиля ролика —
      правки текстом остаются), остальное в `edit.json` не трогает (SKILL.md, часть 2). Новый стиль, ещё не
      смонтированный, живёт до перезагрузки страницы.
    - Прослушивание — как звучит ролик: голос прокси `vm prepare` выравнивает к громкости голоса в ролике (−14 LUFS,
      тот же loudnorm); музыка (Web Audio, файл — через `/api/jobs/<id>/audio`, тот же источник) встаёт к голосу и на
      `gainDb` ниже, с повтором трека и затуханиями движка; звуки — −13 дБ к файлу. Не повторяет приглушение музыки
      под речью и точный LUFS трека (тут — средняя мощность без взвешивания: басовитый трек на прослушивании чуть тише).
      Голос громче 0 дБ элемент видео не даст — тогда тише всё остальное, баланс тот же. Прокси задач, разобранных до
      фазы 3, — без выравнивания (`vm prepare` делает файлы редактора один раз).
    - Громкость звуков — по ключам `insert:<n>`, `teaser`, `transition:<n>`, `end` (номер — в `edit.json`): если сессия
      по правке текстом переставит вставки, громкость достанется соседней. Редко; уйдёт в фазе 5, когда вставки станут
      клипами таймлайна.

15. **CI — чтобы Павлу не проверять руками (12.10).** На каждый пуш, на PR в `master` (слитый с ним код) и каждую ночь
    на `master` (что сломалось снаружи: зеркала apt, модели, браузеры, шрифты): тесты и типы страницы; e2e всего пути —
    в Chromium и в Safari (WebKit на iPhone 13: Павел работает с телефона); на каждом снятом экране телефона страница
    не шире экрана; шаблон — и «Safari рисует превью там же, где рендер» (рамки всего нарисованного в WebKit и
    Chromium — до 4 px или 3 %); движок — быстрые тесты, ruff и медленные с моделями; shellcheck и actionlint;
    CodeQL — уязвимости страницы, движка и workflow (находки — в логе задания; проверенные ложные — в
    `.github/codeql/accepted.json` с причиной: так задание падает только на новых); gitleaks — токены во всей истории
    коммитов; `npm audit` — известные уязвимости зависимостей страницы. Скриншоты e2e обоих браузеров каждый пуш
    кладутся в ветки `ci-screens/<браузер>/<ветка>` (один коммит, перезаписывается): артефакты GitHub из облачной
    сессии недоступны, а ветку Claude забирает `git fetch` и смотрит каждый экран — так каждое изменение видно глазами. Здесь WebKit не ставится (CDN Playwright закрыт прокси), поэтому
    тесты Safari локально пропускаются, а в CI обязательны (`REQUIRE_WEBKIT=1`). Сбой ночного прогона GitHub
    присылает Павлу письмом.

16. **Фаза 4а (12.10): куски в любом порядке.**
    - `keep` — порядок финала, а не исходника: отрезки в любом порядке, без пересечений (момент исходника — не больше
      одного раза; один кусок дважды — в отложенное). Правка `move {t0, t1, before}` ставит оставленное в [t0, t1]
      перед моментом исходника `before` (внутри куска — кусок делится; `null` — в конец). Задачи по порядку исходника
      монтируются ровно как раньше — общие фикстуры `timeline-map.json` и `edits.json` с теми же ответами.
    - Серия — соседние в финале куски, что и в исходнике идут подряд. Акценты, призыв, вставки, ч/б тянутся от своего
      начала только до конца своей серии (`Timeline.span`): переставленный кусок их не уносит и не растягивает через
      чужие куски. Слова субтитров — в порядке, в котором их слышно; группа не переходит через стык серий (`run_of`).
    - Вырезанное при перестановке возвращается к куску, что перед ним в исходнике (в его конец; у `restore` есть `next`
      — к следующему, так тянется начало куска); «＋» стоит там, куда вернётся, а две метки на одном стыке — каждая в
      своём куске. Край куска тянется не дальше соседа по исходнику — куски не наезжают.
    - В редакторе кусок тянут мышью (пальцем — выбранный: иначе палец листает дорожки), линия показывает место; в панели
      куска — «← Раньше», «Позже →» и «Кусок n из m». Переставленный кусок остаётся выбранным, плейхед — в его начале.
      Плеер — тот же `<video>`: переход к куску из другого места исходника — перемотка, как у вырезанного.
    - Рендер переставленного куска проверен по кадрам (`test_render`); e2e перетаскивает кусок, ставит «Позже», отменяет
      и сверяет порядок кусков с движком.

17. **Фаза 4б (12.10): несколько видео в одной задаче — один исходник.**
    - Видео задачи — ассеты `source`, `source-2` … `source-10` (до 10, вместе до 3 ГБ), куски — как раньше. В конце
      загрузки страница шлёт их список (`videos`, по порядку), сервер сверяет каждое по кускам и кладёт в
      `manifest.json`; одно видео — манифест прежний. `vm fetch` кладёт их в `in/source.*`, `in/source-2.*` …, а
      `vm prepare` склеивает по номеру (не по имени: `source-10` — после `source-9`) тем же `normalize`, что и раньше
      склеивал части: дальше движок, сессия и редактор работают с одним исходником — ни правил, ни шагов рутины не
      меняем. «Двух `<video>` попеременно» (§5, фаза 4) не нужно: прокси — тоже одним файлом.
    - Где какое видео — `editor.json.videos` (по длине каждого в целых кадрах, как его звук в `normalize`; стоп-кадр
      под длинную озвучку — у последнего) и строка сводки `prepare` для сессии; имена — как у Павла, из `job.json.videos`.
    - На загрузке — список видео: добавить, поднять выше, убрать; длительность — каждого и вместе. Продолжение после
      перезагрузки — когда выбраны те же видео (в любом порядке, ничего лишнего). Задача называется по первому видео
      и числу остальных («IMG_1.MOV + 1»).
    - В редакторе куски делятся на стыках видео (стык — не край куска: его не тянут), на куске — номер видео, в панели
      куска — время внутри своего файла, справа — список видео задачи с переходом к первому куску каждого (вырезано
      целиком — так и сказано).

### Ревью фазы 4 и CI (свежий агент, 12.10)
Python и TS совпали на 12 000 случайных шкалах (keep в любом порядке, все правки и запросы `Timeline`), токены — на
сервере, имена ассетов и `releaseId` проверены. Важное — исправлено с тестами:
- кусок, поставленный в начало, раздувал память рендера: все отрезки шли из одного декодера, и кадры кусков «из
  прошлого» копились, пока склейка ждала первый (40 с исходника — 5,5 ГБ, двухминутный ролик — 10–17 ГБ). Теперь
  отрезки раскладываются по входам того же файла так, что каждый читает свои строго по возрастанию исходника
  (`decoders`: столько входов, сколько нужно; по порядку — один, как раньше; тизер — частный случай);
- хук тянулся за `hook.until`: переставленный в начало кусок удлинял его на свою длину и выталкивал вставки — теперь
  хук длится, сколько при порядке исходника (`Timeline.in_source_order`), в движке и в редакторе;
- конец слова в вырезанном уезжал к началу следующего по исходнику куска, где бы тот ни стоял (слово висело секунды) —
  теперь конец своего куска (`span`); слова акцента прятались и там, куда их переставили, — теперь только в серии
  акцента;
- зум считался по порядку ролика: переставленный кусок брал крупность соседа — теперь в начале каждой серии крупность,
  какая у неё по порядку исходника;
- «Продолжить загрузку» после перестановки видео шла в старом порядке — продолжение только с тем же порядком;
- видео с «непривычным» расширением (.MTS и т. п.) молча выпадало из склейки — берётся любое, а пропавшее видео
  задачи `prepare` называет и останавливается.

Мелочи — тоже исправлены: доля такта не переносит вставку через стык в чужую серию; кнопки «выше» и «убрать» на
загрузке — по 44 px; то же видео с iPhone (новое время изменения при повторном выборе) не добавляется дважды; битый
список видео в незаконченной загрузке не продолжается; сервер сам проверяет «все видео вместе до 3 ГБ»; выделение в
редакторе не прыгает после непринятой перестановки; скриншоты отменённого прогона не перезаписывают свежие; gitleaks
проверяется по sha256 и работает без токена; `npm audit` — по ночам; разбор SARIF берёт уровни правил и из пакетов
запросов. Продолжение загрузки после перезагрузки в Safari — отдельный шаг e2e (в общем шаге с двумя видео, вставкой и
озвучкой WebKit на Linux зависал на следующем переходе; по отдельности всё проходит — причина не найдена).

Критичного нет: пути звука и картинок не выходят из `jobs/<id>/` и `assets/`, токены остаются на сервере, проверка

## 9. Отложенное
- «Монтировать» в редакторе горит, пока в ветке есть правки руками, даже если ролик смонтирован уже с ними: `vm render`
  стоит записывать ревизию `timeline.json` в `result.json`, а редактор — сравнивать с ней (ревью фазы 3).
- Хвост ролика (стоп-кадр и карточка) на прослушивании не играется — плеер стоит на последнем кадре; карточка на
  кадре — с фазой 5.
- Монтаж по тексту (удалил слова в расшифровке — вырезался кусок), как в Descript и veed — после фазы 5, данные уже есть.
- Один кусок исходника в ролике дважды (повтор фразы, «ещё раз крупно») — `keep` пока без пересечений (фаза 4а).
- Несколько видеослоёв, картинка в картинке, B-roll — после фазы 5.
- Кривые громкости, ключевые кадры, правка переходов.
- Другие форматы кадра (1:1, 4:5, 16:9) и экспорт 4K.
- Премиум-чистка через внешний API или GPU-модель (MossFormer2_SE_48K) — после A/B фазы 6.
